# ChatBI 结构化需求文档 v1.0（终稿）

---

## 一、需求概述

| 项目 | 内容 |
|------|------|
| **产品名称** | ChatBI —— 面向数据分析的自然语言交互式分析系统 |
| **核心目标** | 让非技术用户通过自然语言完成数据分析，降低 BI 使用门槛，提升分析效率 |
| **目标用户** | 业务分析师、产品经理、运营人员（无需掌握 SQL / BI 工具） |
| **典型场景** | 用户输入"上周各渠道的 GMV 和转化率" → 系统解析意图 → 生成并执行 SQL → 返回图表 + 文字解读 |
| **LLM 方案** | 云端 API（OpenAI / Claude / 国内兼容接口），仅传递元信息，原始数据不出域 |
| **数据源策略** | 插件化接入，MVP 阶段用 Mock 数据源验证核心链路，后续按需接入真实数仓 |

---

## 二、功能需求

### P0 核心功能（MVP 必须交付）

#### F1 自然语言理解（NLU）
解析用户输入，提取：**分析意图、指标、维度、时间范围、过滤条件**。

#### F2 业务语义层（Semantic Layer）
- 维护「业务术语 → 物理表/字段」映射（YAML 配置文件，MVP 阶段）
- 支持：同义词注册、指标口径定义、计算逻辑（如 `GMV = SUM(amount) WHERE status='paid'`）
- **LLM Prompt 与语义模型解耦**，语义变更只改配置，不改代码

#### F3 查询规划与 SQL 生成
- 基于语义解析结果，由 LLM 生成可执行 SQL
- 支持多步规划：子查询、JOIN、聚合、窗口函数
- **安全约束**：生成的 SQL 仅允许 `SELECT`，白名单校验，参数化处理防注入

#### F4 查询执行与结果返回
- 通过**数据源适配器（插件）**执行 SQL
- MVP 内置 Mock 适配器（返回预设数据），并预留真实适配器接口
- 返回：结构化表格数据 + LLM 生成的文字分析解读

#### F5 结果可视化
根据返回数据结构自动推荐图表类型（折线图 / 柱状图 / 饼图 / 数字卡片），前端渲染。

---

### P1 重要功能（第一迭代）

#### F6 多轮对话上下文管理
- 支持追问，上下文在 Session 内有效（不跨会话持久化）
- 示例："那按城市细分呢？" → 自动继承上轮的时间范围和指标

#### F7 澄清与反问机制
- 意图模糊或存在歧义时，主动反问用户，而非猜测执行或直接报错
- 示例：输入"最近的情况" → 系统反问："请问是最近 7 天还是 30 天？"

#### F8 查询过程透明化
- 向用户展示「系统理解摘要」（解析结果）和「生成的 SQL」
- 支持用户查看，后续可扩展为手动修正

#### F9 权限与查询约束控制
- 行级数据权限：用户只能查询授权数据域
- 查询复杂度限制：预估代价超阈值则拦截，引导用户缩小范围
- 敏感字段脱敏（配置驱动）

---

### P2 扩展功能（后续迭代）

#### F10 语义模型可视化管理后台
业务用户自助维护指标口径、同义词，无需修改配置文件。

#### F11 真实数据源适配器
按需实现 ClickHouse / MySQL / Hive 等适配器，接入企业真实数仓。

#### F12 指标异动自动归因
检测到数据异常时，自动触发下钻和对比分析。

#### F13 分析报告导出
将对话式分析整理为 PDF / PPT 报告。

## 三、非功能需求

| 类别 | 要求 |
|------|------|
| **响应性能** | 普通查询端到端 ≤ 8s（含 LLM 调用 + 查询执行）；复杂查询异步返回 ≤ 60s |
| **并发** | 支持 ≥ 50 路并发分析请求 |
| **准确性** | SQL 生成准确率（人工抽检）≥ 85%；意图识别准确率 ≥ 90% |
| **数据安全** | 发送给 LLM 的内容**仅含元信息**（表结构、字段描述、语义配置 + 用户 Query），原始业务数据不离开本地；API Key 服务端统一管理 |
| **查询安全** | 仅允许 SELECT；白名单校验；参数化查询防注入 |
| **可观测性** | 每次请求记录：原始输入、解析结果、生成 SQL、执行耗时、是否报错、LLM token 消耗 |
| **可用性** | 服务可用性 ≥ 99.5%；LLM API 异常时返回友好降级提示 |

## 四、边界与约束

### 不做什么（MVP）
- ❌ 不支持实时流数据查询
- ❌ 不提供数据写入/修改能力（只读）
- ❌ 不自动发现数据源，所有数据源须预先注册
- ❌ 不跨 Session 持久化对话历史
- ❌ 不在 MVP 阶段实现语义模型可视化管理界面

### 技术约束
- 语义层用 YAML/JSON 配置文件驱动，与 LLM Prompt 完全解耦
- 数据源通过**适配器接口**插件化接入，MVP 用 Mock 适配器
- LLM 接入须统一封装，支持后续切换模型供应商

### 外部依赖
- LLM 云端 API（OpenAI / Claude / 国内云厂商兼容接口）
- 企业统一身份认证（SSO / LDAP，P1 阶段对接）

## 五、验收标准（Given-When-Then）

### AC-01 基础查询生成
```
Given  语义模型中已注册"订单表"及"GMV"指标
When   用户输入"查询上周各渠道的 GMV"
Then   系统返回：
         - 解析摘要（指标=GMV，维度=渠道，时间=上周）
         - 可执行 SQL（正确的分组聚合与时间过滤）
         - 表格数据 + 柱状图
         - 文字解读（Top 渠道、数值概要）
         - 端到端响应时间 ≤ 8s
```

### AC-02 歧义澄清
```
Given  用户输入"最近的销售情况怎么样"
When   "最近"和"销售情况"存在多种解释
Then   系统反问："请问是最近 7 天还是 30 天？需要查看销售额、订单量还是两者都要？"
       不执行查询，不直接报错退出
```

### AC-03 多轮上下文继承
```
Given  上一轮已查询"上周各渠道 GMV"
When   用户追问"那退款率呢？"
Then   系统继承上轮时间范围（上周）和维度（渠道），
       生成退款率查询，无需用户重复描述上下文
```

### AC-04 权限拦截
```
Given  用户 A 无 finance 数据域访问权限
When   用户 A 请求"查询各部门薪资分布"
Then   系统返回权限不足提示，不生成也不执行任何 SQL
```

### AC-05 高危查询拦截
```
Given  系统配置了查询复杂度阈值（预估扫描行数 > 1 亿）
When   生成的 SQL 触发阈值告警
Then   系统拦截执行，提示用户缩小范围并给出建议（如"请增加时间过滤条件"）
```

### AC-06 语义缺失处理
```
Given  用户查询包含语义模型中未注册的指标"活跃度"
When   系统无法完成映射
Then   系统告知"暂不支持该指标"，并列出当前可查询的相关指标供用户选择
```

### AC-07 数据源适配器隔离（MVP 专项）
```
Given  Mock 适配器已注册，真实数据库未接入
When   系统执行生成的 SQL
Then   Mock 适配器返回预设数据，核心链路（NLU→语义→SQL生成→执行→可视化）完整跑通，
       切换为真实适配器时无需修改上层代码
```

### AC-08 LLM 数据安全
```
Given  用户发起任意分析请求
When   系统调用 LLM API
Then   请求体中仅包含：用户 Query + 表结构元信息 + 语义配置
       不包含任何实际业务数据（表中的真实行数据）
```
